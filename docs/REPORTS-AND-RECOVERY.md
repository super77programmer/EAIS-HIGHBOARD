# Class reports and desktop refinements — 13 October 2026

Teachers can create private reports for assigned classes, optionally select an active student in that class, save drafts and submit observations to school staff. Categories cover progress, attendance, behavior and general observations. School staff and roster administrators can review submitted reports and send feedback with Submitted, In review or Resolved status. Drafts remain visible only to their author; students, council members and unsigned visitors cannot use this endpoint. Submitted observations are immutable; revision checks protect concurrent editing and review. Report content is not copied to the public board or persisted in browser storage. Requests are origin-checked, rate-limited and bounded; audit events record actions without report text. The database migration adds an isolated teacher_reports table.

The Reports navigation item and staff Home shortcut appear only for signed school teachers/staff/administrators. A teacher with no assigned classes sees an explanatory empty state. The page includes search, status filters, class/student/date/category/priority controls, staff feedback and retry behavior. Failed saves retain the current report text and identifier. Identity invalidation clears private details.

Application JSON responses now use a shared reader. Hosting HTML, redirects, empty responses and malformed payloads produce readable recovery messages. HTML is never cached as an inbox response. Recent production logs contained successful requests and one expected unauthorized API response; they did not establish the source of the reported HTML response. This change handles that failure safely rather than claiming a proven hosting root cause.

Home keeps announcements and tasks in the primary column and agenda/reminders beside them. Trips, upcoming dates and lunch sit in a separate discovery row on tablet/desktop, with mobile content order retained. Subtle surface/detail transitions, focus states and warm hover treatment respect reduced motion. The completed agenda resource footer, calendar provenance and school role permissions remain intact.

Validation: real SQLite route tests cover report privacy, class/student scopes, review workflow, concurrent revisions, immutable submissions, inactive accounts, revoked assignments, CSRF and bounded payloads. DOM tests cover scoped selection, preserved failed-save drafts, stable retry identifiers and identity clearing. Shared-reader/cache tests cover HTML and malformed API responses. Existing messaging, waveform/voice gestures, calendar, agenda, planner, trips and publishing suites are retained. TypeScript and structural file checks are run before publication. Pixel-level browser QA is unavailable in this managed environment.
